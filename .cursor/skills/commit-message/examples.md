# コミットメッセージ例

## 基本形

```
<タイプ>: <What>

- <Why（1〜2文）>

Refs #123
```

## タイプ別

### feat — 新機能

```
feat: 未ログイン時にスタンプボタンを非表示にした

- 未ログインでタップしても利用できず混乱を招くため、導線を絞った

Fixes #7
```

### fix — バグ修正

```
fix: わいわいリクエスト一覧取得を listFeatureRequests に統一した

- 取得経路が分岐しており、レスポンス形式が揃わない不具合があったため

Refs #42
```

### docs — 仕様・ドキュメント

```
docs: ユーザー認証の受入基準を追加した

- ログイン失敗時の挙動が未定義だったため、仕様を明文化した

Refs #15
```

### refactor — 振る舞いを変えない整理

```
refactor: useMarkerFilterContext のモックをテスト用に切り出した

- 複数テストで同じセットアップが重複していたため
```

### test — テスト追加・更新

```
test: feature-requests API のルートテストを追加した

- 受入基準のエッジケースをカバーするため
```

### chore — 依存・設定・雑務

```
chore: vitest 用に jsdom を追加した

- コンポーネントテストの実行環境が不足していたため
```

## Issue 参照

| キーワード   | 用途                            |
| ------------ | ------------------------------- |
| `Fixes #123` | このコミットで issue を解決する |
| `Refs #123`  | 関連するが自動クローズしない    |

## 避ける例

| 悪い例                     | 理由                                                       |
| -------------------------- | ---------------------------------------------------------- |
| `Add login feature`        | タイプがない                                               |
| `fix: Fixed the bug.`      | 英語・末尾ピリオド・What が不明確                          |
| `Update dependencies`      | `chore: 依存関係を更新した` のようにタイプと What を付ける |
| Why なしで実装詳細だけ列挙 | 変更理由が伝わらない                                       |

## コミットコマンド例

```bash
git commit -m "$(cat <<'EOF'
docs: ユーザー認証の受入基準を追加した

- ログイン失敗時の挙動が未定義だったため、仕様を明文化した

Refs #15
EOF
)"
```
