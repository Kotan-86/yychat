## 目的（Why）

既存の音声認識アプリ（初回検証ホストは YY文字起こし）は、すでに入力 UI・認識・（送信時の）読み上げを持つ。プロトタイプで検証した「入力途中からの確定読み上げ＋効果音」（方式A）を、画面見た目を押し付けずに差し込めるようにしたい。

ホスト実装者は「どの入力事実を渡し、どの結果を購読すれば方式Aが動くか」だけ分かれば足りる。Feature 向けの内部イベント組み立てや、タイムライン／下書きの画面規約を SDK の受入に混ぜないことで、[タイムライン画面仕様](timeline-screen.md) と配布境界を分け、組み込み先の既存 UI を壊しにくくする。

境界の根拠は [ADR: 発言支援ロジックの外部ライブラリ化方針](ADR_speech-support-library.md)（案B・方式A・SPM・ホスト薄い入口）である。

## 実現内容（What）

### 1. 配布物

- **方式A（確定読み＋デバウンス＋効果音）までの発言支援 SDK**（UI なし）を配布する
- 配布形態は **Swift Package（ソース配布）** とする
- 公開 API は特定アプリ名に依存しない（初回受入ホストは YY文字起こしに限定するが、契約はアプリ非依存）

### 2. ホストが渡す入力事実

ホストは次の事実のみを SDK に渡す。分類（変換中の増減か、確定テキスト変化か）はホストが組み立てない。

| 入力             | 内容                                               | 必須                                                                |
| ---------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| テキスト変化     | 現在テキスト ＋ IME 未確定かどうか                 | 必須（変化のたびに）                                                |
| Return／送信相当 | 押下の事実                                         | 任意（渡してもよいが、方式Aの既定発言支援では再読み上げに使わない） |
| 効果音の差し替え | 役割単位（打鍵／削除など）で、既定の代わりに使う音 | 任意                                                                |

### 3. ホストが受け取る結果

| 結果               | 内容                                                         | ホストの反映                                                               |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| クリア要求         | 入力欄を空にしてほしい旨（または表示状態としての空テキスト） | ホストが自画面の入力欄を空にする。SDK は特定の入力ビュー所有を前提にしない |
| 読み上げ対象文字列 | デバウンス確定読みの対象になった文字列（spoken）             | 下書き／履歴などへの反映はホスト。SDK は会話ログ UI を持たない             |
| 読み上げ中         | 読み上げ再生中かどうか                                       | ホストが既存仕様どおり認識のストップ／再開に使う                           |

### 4. 方式Aの振る舞い（SDK が保証する）

- **デバウンス確定読み**: IME が未確定でない確定テキストがあり、入力が **0.5 秒** 止まったら、その確定テキストを読み上げる
- **空白のみは対象外**: 確定テキストを前後空白で除いた結果が空のときは、読み上げ・spoken 通知・クリア要求をいずれも行わない
- **デバウンス待機中の取消**: デバウンス完了前に確定テキストが空（または前後空白のみ）になったときは、直前の候補を読み上げない。待機中の読み上げは取り消される
- **変換中効果音**: IME 未確定中、文字の追加・削除に応じて役割の異なる効果音が鳴る
- **読み上げ中の効果音抑制**: 読み上げ再生中は効果音を鳴らさない。読み上げ終了後、効果音を再開する
- **読み上げ中の入力継続**: 読み上げ再生中も、ホストの入力欄への追加入力は可能である（入力欄自体はホストが提供）
- **読み上げ成功後の通知**: 読み上げが開始できたとき、読み上げ対象になった文字列を spoken として通知し、クリア要求を出す。入力欄の空反映と下書き／会話ログへの蓄積はホストが行う。SDK はタイムライン追加や下書き更新を自ら行わない
- **読み上げ失敗時**: 読み上げを開始できなかったときは、spoken 通知もクリア要求も出さない
- **効果音の既定同梱**: 差し替えを指定しなくても、同梱の既定アセットで上記の変換中フィードバックが鳴る
- **効果音の差し替え**: ホストは役割単位で既定音を差し替えられる。差し替えは任意であり、未指定時に効果音が欠落してはならない

### 5. セッションと配線

- ホストは「セッションを作り、入力事実を渡し、結果を購読する」だけで方式Aが動く
- セッション生成と内部 Feature の配線は SDK 内で完結する
- **Audio Session はホスト専有**とする。SDK はカテゴリ設定・アクティブ化を行わない

### 6. ホスト製品との併存（ホスト側の責務）

- 既存の「送信時の全文読み上げ」と方式Aは **併存**する。設定で切り替え可能とする（設定 UI・送信時読み上げ本体はホスト）
- SDK 導入で送信時読み上げを廃止しない
- 読み上げ中の音声認識ストップ／終了後の再開は、既存 YY 系アプリ仕様に合わせ **ホストが行う**（SDK は読み上げ状態を通知する）

### 7. 含めないもの

- 音声認識クライアントおよび認識結果の表示
- タイムライン／チャット等の会話ログ UI、下書き蓄積・送信ルール（案C）。spoken 通知後の下書き表示・タイムライン追加・Return 送信はホストの画面仕様に属し、SDK の結果契約に含めない
- Feature が購読するドメインイベント（内部イベントストリーム）のホスト公開
- 各 Feature 実装・Speech／効果音プレイヤーの実装詳細のホスト必須契約化
- 効果音ファイルの内部パスやバンドル構造をホスト必須契約にすること（未差し替え時に同梱音が鳴ることのみ受入とする）
- **方式B（1文字ずつ読み）** を製品 SDK の既定・推奨・公開契約に含めること（方式切替 UI も含めない）
- Return／送信時の **再読み上げ**（方式Aの既定発言支援に含めない。Return／送信相当の入力事実を受けても再読み上げしない）
- YYProbe への初回組み込み検証（初回ホストは YY文字起こしに限定。本番マージ可否は別判断）

## 受入基準

1. **入力事実だけで方式Aが動く**: ホストが「現在テキスト＋IME 未確定か」のみを渡し、内部ドメインイベントを組み立てないとき、方式A（デバウンス確定読み・変換中効果音・読み上げ中の効果音抑制）が動作する。
2. **デバウンス確定読み**: IME 未確定でない確定テキスト（前後空白を除いても空でない）を入力し、その後 0.5 秒以上入力が止まったとき、その確定テキストが読み上げられる。
3. **空白のみは読み上げない**: 確定テキストが前後空白のみのとき、0.5 秒以上入力が止まっても読み上げ・spoken 通知・クリア要求は発生しない。
4. **デバウンス待機中の取消**: 非空の確定テキストを渡したあと、デバウンス完了前に空（または前後空白のみ）へ更新したとき、その後デバウンス間隔以上待っても読み上げ・spoken 通知・クリア要求は発生しない。
5. **変換中効果音**: IME 未確定中に文字を追加したときと削除したときで、それぞれ異なる効果音が鳴る。
6. **読み上げ中の効果音抑制**: 読み上げ再生中に IME 未確定の追加・削除を行っても効果音は鳴らない。読み上げ終了後は、未確定の追加・削除で再び効果音が鳴る。
7. **spoken とクリア要求**: デバウンス確定読みが開始できたとき、読み上げ対象文字列（spoken）が通知され、クリア要求が出る。ホストがクリア要求に応じて入力欄を空にしたとき、編集可能な入力は空になる（SDK が特定の入力ビューを直接空にすることを前提にしない）。
8. **読み上げ失敗時は通知しない**: デバウンス確定読みを開始できなかったとき、spoken 通知もクリア要求も出ない。
9. **下書き・タイムラインはホスト**: spoken 通知後、下書き表示やタイムライン追加の有無はホストの画面仕様に従う。SDK 単体の受入では会話ログ UI の更新を要求しない。SDK は spoken／クリア以外にタイムライン追加や下書き更新を行わない。
10. **効果音の未差し替え**: 効果音の差し替えを一切指定しないときでも、変換中の追加・削除で同梱の既定効果音が鳴る。
11. **効果音の差し替え**: 役割単位（打鍵／削除など）で差し替え音を指定したとき、該当操作では差し替え音が鳴り、未指定の役割は既定音のまま鳴る。
12. **読み上げ中フラグ**: 読み上げ開始から終了まで「読み上げ中」が真となり、終了後は偽となる。ホストはこの値を見て認識のストップ／再開を行える。
13. **Audio Session 非所有**: SDK の発言支援経路が、Audio Session のカテゴリ設定およびアクティブ化を行わない。
14. **方式B・Return 再読み上げは製品対象外**: 製品 SDK の公開契約・既定の発言支援に、方式B および Return／送信時の再読み上げが含まれない。Return／送信相当の入力事実だけを渡しても、SDK は再読み上げしない。
15. **認識・UI 非同梱**: SDK に音声認識クライアントおよびタイムライン／入力画面の View・Storyboard が含まれない。
16. **公開面の閉鎖**: ホストが方式Aを動かすために、Feature 向けドメインイベントや各 Feature クラスの利用を必須とされない（入力通知と結果購読で足りる）。
17. **送信時読み上げとの併存方針**: ホスト製品において、既存の送信時読み上げと方式Aを設定で切り替え可能であり、SDK 導入のみを理由に送信時読み上げが廃止されない（設定 UI・送信時読み上げ本体はホスト側の受入）。
