## 目的（Why）

発言支援 SDK（方式A）の初回組み込み検証ホストは YY文字起こしに限定する（[ADR: 発言支援ロジックの外部ライブラリ化方針](ADR_speech-support-library.md)）。本番マージの可否は、ホスト差分（既存の送信時読み上げ・IME・Audio Session・認識排他など）を YY文字起こし上で確認してから別途判断する。

本ドキュメントは、その判断に必要な **確認項目だけ** を固定する。本番コードへの組み込みやマージを要求しない。

## 実現内容（What）

### 1. スコープ

| 含む                                                                | 含まない                                 |
| ------------------------------------------------------------------- | ---------------------------------------- |
| YY文字起こし上でのスパイク確認項目と、合格／不合格の判定観点        | YY文字起こしへの本番組み込み・本番マージ |
| [発言支援 SDK 仕様](speech-support-sdk.md) のホスト契約に沿った確認 | YYProbe 上の確認（初回スコープ外）       |
| 既存機能（送信時読み上げ・認識・入力 UI）を壊さないことの確認       | 方式B・案C（下書き／送信ルール）の製品化 |

### 2. 確認項目（ホスト差分）

スパイクでは次を確認する。いずれも SDK 公開契約（入力事実の受け渡しと結果購読）の範囲で足りること。

#### 2.1 送信時読み上げと方式Aの設定切替

- 既存の「送信時の全文読み上げ」と方式Aは **併存**する
- ホスト製品の設定で、どちらを使うか（またはどちらを有効にするか）を切り替えられる
- 設定の意味（排他か独立か）をホスト製品として明示し、二重読み上げにならない組み合わせを選べる
- SDK 導入のみを理由に、送信時読み上げを廃止しない

#### 2.2 IME 事実の取り方

- ホストが「現在テキスト ＋ IME 未確定かどうか」を、入力変化のたびに SDK へ渡せる
- ホストが変換中／確定の分類や Feature 向け内部イベントを組み立てなくても、方式A（デバウンス確定読み・変換中効果音）が動く

#### 2.3 クリア反映

- SDK がクリア要求（または表示状態としての空テキスト）を出したとき、ホストが自画面の入力欄を空にできる
- クリア後も、既存の入力欄ライフサイクル（フォーカス・IME・送信フロー）が維持される
- SDK が特定の入力ビュー所有を前提にしなくても足りる

#### 2.4 共有 Audio Session

- Audio Session はホスト専有のままである（カテゴリ設定・アクティブ化はホスト）
- SDK の発言支援経路が Audio Session のカテゴリ設定・アクティブ化を行わない
- ホストがすでに握っている録音用セッション上で、方式Aの TTS／効果音が再生できる

#### 2.5 読み上げ中（`isSpeaking`）→ 認識のストップ／再開

- SDK が「読み上げ中かどうか」を通知する
- ホストが既存 YY 系アプリ仕様どおり、読み上げ中は音声認識をストップし、終了後に再開できる
- 認識クライアント自体は SDK に含まれない（ホスト資産のまま）

#### 2.6 効果音の差し替え

- 差し替えを指定しなくても、同梱の既定効果音で変換中フィードバックが鳴る
- ホストが役割単位（打鍵／削除など）で差し替え音を指定したとき、該当操作では差し替え音が鳴る
- 未指定の役割は既定音のまま鳴る

### 3. 本番マージ可否

- 上記確認の結果をもって、YY文字起こしへの本番組み込み可否を **別判断** する
- 本スパイク文書の完了は、本番マージの承認を意味しない

## 受入基準

1. **設定切替**: YY文字起こし上で、送信時読み上げのみ有効・方式Aのみ有効・（製品が許すなら）両方オフ、など設定どおりに切り替わり、意図しない二重読み上げが起きない組み合わせを選べる。
2. **送信時読み上げの存続**: 方式Aを有効にしても、設定で送信時読み上げを再び有効にでき、送信時読み上げ本体が廃止されていない。
3. **IME 事実**: ホストが「現在テキスト＋IME 未確定か」のみを渡したとき、方式A（IME 未確定中の効果音、および確定テキストの 0.5 秒デバウンス読み）が動作する。
4. **クリア反映**: デバウンス確定読みが開始できたときクリア要求が出て、ホストが入力欄を空にした結果、編集可能な入力が空になる。既存のフォーカス／送信フローが破たんしない。
5. **Audio Session**: スパイク中、SDK 経路が Audio Session のカテゴリ設定・アクティブ化を行わず、ホスト既存セッション上で TTS／効果音が再生される。
6. **認識排他**: 読み上げ開始から終了まで「読み上げ中」が真のあいだ認識がストップし、終了後（偽になったあと）に認識が再開される。
7. **効果音**: 未差し替えでも同梱音が鳴り、役割単位で差し替えた操作では差し替え音が鳴る。
8. **本番非要求**: 本確認リストを満たしても、YY文字起こしへの本番マージは自動では行わない（別判断の記録が残る）。
