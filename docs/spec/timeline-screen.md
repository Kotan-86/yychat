# 音声認識と音声合成を統合したタイムラインコミュニケーション画面

## 背景（Why）

* 既存の YY 系アプリでは、文字起こしとチャット入力が混在し、会話の流れが読み取りづらい
* 発言支援（音声合成）だけでは、相手の発話を同じ画面で時系列に追えない
* 聴者には入力途中から届けつつ、会話ログとして見えるのは「確定した発話」に揃えたい

## 目的（What）

* 発言支援（音声合成）と受信支援（音声認識）を単一画面に統合し、双方向コミュニケーションを成立させる
* 音声認識は YYAPIs 経由で受け取り、タイムライン上に相手の発話を表示する
* 自分の発話は、聴者に届けた内容（デバウンス読み上げ済み）と、会話ログ（Return 送信）を分離する
* 入力読み上げは [ADR: 入力読み上げ方式](ADR_feature-reads-method.md) の方式A（確定読み＋デバウンス＋効果音）に一本化する

## 画面構成

単一画面に、次の3領域を置く。

| 領域 | 役割 |
|------|------|
| **タイムライン領域** | 確定した送受信メッセージのみを時系列表示する |
| **下書き領域** | デバウンス読み上げ済みの自分の発話を閲覧表示する（編集・追記不可） |
| **入力領域** | 自分の未送信テキストを編集する（実装上は `UITextView` 等1つでもよいが、役割は入力専用） |

## スコープ

### 含む

* タイムライン・下書き・入力の3領域による UI
* 相手1人分の音声認識結果のタイムライン表示
* 方式Aに基づく発言支援（デバウンス読み上げ・効果音）と Return による送信

### 含まない

* 複数話者の受信表示（既存アプリ側で対応済み。本画面は相手1人を想定）
* メッセージの永続化・編集・削除
* Return 押下時の再読み上げ
* 入力欄に未読み上げの文字列が残っている状態でのタイムライン送信

## 受け入れ条件

### タイムライン表示

* メッセージは**上が古い / 下が新しい**順で、スクロール可能なタイムライン領域に並ぶこと
* タイムラインには**確定した送受信メッセージのみ**が表示され、自分の未送信入力は表示されないこと
* **相手（受信）**: 左寄せ、背景色は黒（LINE 風のバブル配置）
* **自分（送信）**: 右寄せ、背景色は白（LINE 風のバブル配置）
* 左右の配置と背景色により、送受信が判別できること
* 本文は、各背景色上で読み取り可能なコントラストであること

#### 未確定・確定の受信表示

* 音声認識の最初の partial（1文字目）で、新しい受信バブルを作成すること
* 確定前は、同一バブル内のテキストが更新され続けること
* final 受信後、そのバブルが視覚的に「確定」状態となり、未確定状態と区別できること
* final が空、または認識失敗相当のとき、当該バブルを表示から除去すること

#### 自動スクロール

* 追従モード中に、タイムラインへメッセージが追加されたとき、**最新メッセージの先頭行**が画面内に見えるようスクロールすること（「露出」の定義）
* 下書き領域の更新のみでは、タイムラインの自動スクロールを行わないこと
* ユーザーがタイムラインを手動スクロールしている間は、自動追従しないこと
* 画面下部の操作により、自動追従を再開し、最新メッセージへスクロールできること

### 下書き領域

* デバウンスによる読み上げが行われたあと、読み上げ対象となった文字列が下書き領域に表示され続けること
* 下書き領域の文字列は、ユーザーが編集・追記できないこと（閲覧のみ）
* 下書き領域の内容は、Return による送信までタイムラインに表示されないこと
* デバウンス読み上げ後、編集可能な入力領域の文字列は空になること（続きの入力は入力領域から行う）

### 音声認識（文字起こし）による受信支援

* 音声認識モジュール（YYAPIs）から認識途中のテキスト（未確定データ）を受け取った際、タイムライン上の該当メッセージのテキストがリアルタイムかつ非同期に更新されること
* 音声認識モジュールから認識完了の通知（確定データ）を受け取った際、そのメッセージの表示が確定され、以降の音声認識は新しいメッセージとしてタイムラインに追加されること
* 受信は**相手1人**の発話のみを想定すること
* 音声認識データの受信およびタイムラインへの描画処理中、ユーザーのテキスト入力操作や画面のスクロールがブロック（フリーズ）されないこと

### 発言支援（方式A）

* [ADR: 入力読み上げ方式](ADR_feature-reads-method.md) の方式A（確定読み＋デバウンス＋効果音）に従うこと
* IME 未確定中、文字の追加・削除に応じて効果音が鳴ること
* 漢字変換確定後、入力が一定時間止まったら、編集可能な入力領域の確定済みテキストが読み上げられること
* 上記の読み上げでは、タイムラインにメッセージを追加しないこと
* 読み上げの再生中は効果音を鳴らさないこと。読み上げ終了後、効果音を再開すること
* 読み上げの再生中も、編集可能な入力領域への入力は可能であること

### 送信（Return）

* Return 押下時、タイムラインに追加する文字列は**下書き領域に表示されている内容のみ**とすること
* 編集可能な入力領域に1文字以上残っている状態では、タイムラインへの追加を行わないこと
* Return 押下時、音声合成による読み上げを行わないこと
* 下書き領域の文字列を前後空白トリムした結果が空のとき、タイムライン追加・下書きクリア・入力領域クリアをいずれも行わないこと
* 上記以外の Return 押下時、下書きの全文を自分の発言としてタイムラインに1件追加し、下書き領域および編集可能な入力領域を空にすること
